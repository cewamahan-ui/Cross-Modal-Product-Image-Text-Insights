# Ethics note - SokoniHub cross-modal join (Week 10)

Four headings, concrete sentences, one review path. This note is the
responsible-deployment statement a reviewer can repeat back to a manager.

## Photos

The photo side of this join is four hand-authored tag sidecars
(`fixtures/tags/*.json`) over four synthetic Pillow drawings
(`fixtures/images/*.png`) - no live marketplace was crawled and no real
listing photos are in git. There are **no real people, faces or child
photos anywhere in this repository**, and the catalog carries a privacy
flag: `insights.py::privacy_check` marks any SKU whose tags or title
contain person/face/child terms (`privacy_flag: true`), and a human must
clear that flag before anything is published - none of the four fixtures
trip it (`privacy_flags=0` in `evidence/insights_run.log`). Multimodal
bias matters here too: a real tagger inherits blind spots from its
training data (whose faces it names, which products get described
carefully), so these four sidecars are hand-authored rather than
laundering a tagger's gaps as ground truth - and when a real tagger
arrives, `vocab_gaps.json` is where its misses get counted. If real photos
arrive later, they arrive with a Kenya Data Protection Act 2019 basis for
processing (people's images are personal data), not as a scrape.

## Language

Scores describe *word agreement between a listing and its tags*, not
truth: `agreement < 0.35` means "the words disagree and a human should
look", never "this seller is lying". The seller message templates in
`insights.py` are drafts that say "please review before publishing"; they
never rewrite a seller's title (`title_rewritten: false`, proven by
`tests/test_gold.py::test_no_title_overwrite`). We do not claim the model
detects counterfeit brands - NK-99 is flagged for *photo/title
disagreement*, which is a mismatch, not an infringement verdict. The
encoder misses synonyms and Swahili/English mix-ups (`vocab_gaps.json`),
so a flag is a prompt to look, not a verdict.

## Generated pixels

No image was generated by a model in this capstone: there is no OpenAI
image key and no Stable Diffusion checkpoint here, so `gen/stub_render.py`
drew a **labelled placeholder** whose pixels and JSON both carry
`not_a_photo_of_the_sku: true`, pinned to `gen/prompt_still_life.txt` by
sha256. The pinned prompt contains **no people terms** (no people, hands,
faces, children) - the "no people prompts" rule from Thursday holds for
whatever generator is used later, hosted (DALL-E) or OSS twin (Stable
Diffusion). Generated pixels only ever land in `outputs/gen/`; `gold/` and
`fixtures/images/` stay clean. If someone later runs DALL-E or SD for
real, the same prompt pin and the same meta JSON apply - only the status
field flips, with cost and provenance recorded.

## Review path

Any SKU with `flag: true` (currently NK-99) or `privacy_flag: true` is
held as a draft in `insights.json`, a human moderator checks the photo,
title and tags, and only then does the seller-facing message go out -
one sentence: **flag goes to a named human moderator first; no automated
edit and no automated takedown ever touches a live listing.**

Transfer note: AfyaPlus posters/leaflets are a *later* transfer, and
AfyaPlus triage fixtures are deliberately not mixed into this catalog
(`catalog.json` provenance fields show only Week 10 fixtures). Week 9's
DPA/DPIA work carries over unchanged; nothing here re-trains or re-uses
patient data.
